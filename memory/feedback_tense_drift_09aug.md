# ⏳🔴 **A TENSE CHANGE SURVIVED ONE HOP AND BECAME A FIRE**

**09-Aug-2026, Rama's own words:** *"I read the register, believed it, and escalated a future condition into an urgent live one."*

## WHAT HAPPENED — ⛔ nothing was fabricated and no number was wrong

| hop | text | tense | correct? |
|---|---|---|---|
| build record §6 | *"it **will** WARN every morning at boot"* | **FUTURE** | ✅ correct |
| register `N9-02` | *"It **FIRES** EVERY MORNING at boot"* | **PRESENT** | 🔴 **WRONG** |
| the commissioning card | *"⛔ **AND C5b FIRES EVERY MORNING** … a daily false alarm … it trains it on Rama"* | **PRESENT + URGENT** | 🔴 a fire that did not exist |

⭐ **ONLY THE TENSE MOVED.** It converted *"will happen after a deploy that has no date"* into *"is happening to you now"* — and it happened **inside the register built to stop exactly this.**

## **Why:**
⛔ **This is the same class as a conclusion outliving its evidence** — `M3` (line numbers hold ONLY at their measured SHA) and `feedback_status_label_rule_27jul` (**DEPLOYED ≠ VERIFIED LIVE**) are the STATE form of it. **This is the TIME form**, and it had no rule until now. ⭐ For built-but-unpushed code the present tense is not a small imprecision — **it is a claim about production that is false**, and it reads as urgent precisely because a present-tense alarm demands action.

## **How to apply:**
1. 📌 **A register row (or memory line, or report) describing the behaviour of BUILT-BUT-UNPUSHED code MUST carry the tense AND the precondition in the SAME sentence:** *"**WILL** fire, from the first boot **after X deploys**"*. ⛔ **Never a bare present tense.** A precondition in a neighbouring sentence is the thing that gets dropped at the next hop.
2. ⛔ **Compressing for a summary is where it happens.** When shortening someone else's sentence, the modal verb (*will · would · can · may*) is **load-bearing** — ⛔ it is not filler to be trimmed for line budget.
3. ⭐ **The tell to grep for:** any present-tense verb of occurrence (`fires`, `arrives`, `warns`, `runs`, `blocks`) sitting next to a `<BUILT — NOT PUSHED>` / `<NOT DEPLOYED>` label. **The two cannot both be true.**
4. ⛔ **When the premise is urgency, VERIFY THE PREMISE FIRST** — [[feedback-verify-the-finding-premise]]. Here the whole commission rested on one verb, and [[extracted-validator-technique-09aug]] is what refuted it in minutes.
5. ⭐ **Fix the record BOTH ways: correct the drifted row AND record the drift as its own finding.** Correcting only the row leaves the mechanism intact for the next compression. *(Register `N9-12`, opened 09-Aug; N 244 → 245.)*
6. ⛔ **Quote the wrong text inside the correction — never delete it** (`G4`): it is what the measurement is evidence against.

⚠️ **Severity drifted on the same hop and by the same mechanism:** native `WARN` → pre-flight `Criticality.WARN` → Control Tower `HIGH` was retold as **`CRITICAL`**. ⛔ **Never restate a severity from memory — read the mapping.**
