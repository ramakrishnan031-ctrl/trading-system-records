# 📏🔴 **I MIXED TWO BASES IN ONE COMPARISON — THE ERROR THIS PROJECT HAS TWICE BEEN TOLD NOT TO MAKE**

**09-Aug-2026.** I wrote: *"your six-trade worst case measured ~5.25 %, so it sits just above it."*
⛔ **`5.25 %` is of TOTAL capital. `6 %` is of SEGMENT capital. Two different bases, compared as one scale.**

## THE NUMBERS, ON ONE BASE *(intraday book = 70 % × ₹10,000 = ₹7,000)*
| | rupees | % of the ₹7,000 book | % of total |
|---|---|---|---|
| six-trade worst case | **₹525** | **7.5 %** | 5.25 % |
| a 6 % threshold | **₹420** | 6 % | 4.2 % |

⇒ 🔑 **₹525 > ₹420 ⇒ a 6 % threshold FIRES TODAY at current settings. ⛔ It does NOT sit above the worst case — it sits BELOW it.**

## **Why:**
⭐ **The `6 %` itself was right** — 6 % of *that book's own* capital, matching the standing policy FORM (*3 % of each segment's OWN capital*, segment-based deliberately). ⛔ **ChatGPT's ₹600 rebased it onto TOTAL capital, which is not the policy form.** 🔴 **The defect was one layer down and it was mine: the COMPARISON.** ⭐ This is the same family as **C5's own `1/0.70` apples-to-oranges defect** — a fraction of TOTAL set against a fraction of a BUCKET — which this campaign diagnosed and then reproduced within days.

## **How to apply:**
1. 📌 **Every percentage carries its BASE or it is not a number.** Write `7.5 % of the intraday book`, ⛔ never a bare `7.5 %`.
2. ⛔ **Never compare two percentages until both are restated on ONE base** — and show the rupees, which have no base ambiguity at all.
3. ⭐ **When a threshold is proposed, state whether it FIRES TODAY.** A number offered as headroom that actually fires immediately is a different decision, and the operator must choose it knowing which it is.
4. ⭐ **A warning that fires is not automatically wrong** — the ₹525 is real and nothing has ever watched it. ⛔ But *"it sits just above"* was false comfort.
