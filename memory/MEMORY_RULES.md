## Feedback / Rules

### Evidence discipline
- 🧪🕳️🔝 **A JOIN THAT RETURNS ZERO ROWS IS ⛔ NOT A MEASUREMENT UNTIL THE KEY IS PROVEN.** 🔬 10-Sep: `ON e.order_id=o.order_id` returned **0 of 32** in-window fills — reading exactly like "no slippage data exists". ⭐ Different namespaces (internal `ord_*` vs broker id): **0 of 618** can EVER match. ⭐ Count the join's key overlap before reporting an empty result.
- 📊⛔🔝 **A COLUMN THAT IS CONSTANT IS ⛔ NOT A SIGNAL — CHECK ITS POPULATION BEFORE QUOTING IT.** 🔬 10-Sep: *"the legs were CANCELLED at `qty_filled=0`"* looked like proof of a non-fill; `qty_filled` is **0 on all 1,401 rows**, COMPLETE ones included. ⭐ One `SELECT COUNT(*), SUM(col>0)` retires the claim. ⛔ Never let a field's *name* stand in for its *content*.
- 📈✂️🔝 **A SAMPLE OF THINGS THAT SUCCEEDED CANNOT BOUND THE TAIL OF THINGS THAT FAIL.** 🔬 10-Sep: all 7 in-window EOD exits filled inside 0.12 % of a **1 %** limit — but an exit needing more than 1 % never fills, so it cannot appear. ⭐ The sample is **right-censored at the band**; it proves sufficiency 7/7, ⛔ it does not bound the tail. ⭐ Say "censored" out loud whenever the instrument is also the filter.

- 📦🔍🔝 **PRESERVE THE COMPLETE CANDIDATE SET, ⛔ NOT THE INTERESTING MEMBER.** 🔬 31-Aug: preserved `gtt_state` for SPLPETRO only (interesting at 15:23); the question raised at 18:45 needed KOPRAN + DIFFNKG triggers ⇒ ⭐ answerable only while the VM held them. ⇒ ⭐ Snapshot **every row of the class** (all `GTT_EXIT` trades + triggers + exit px + strategy + product + ids), ⛔ never one member.
- ⚖️🕳️🔝 **S-6 — RELAYED RECORD vs YOUR OWN ENUMERATION ⇒ SURFACE THE CONFLICT.** ⛔ Do NOT resolve it by deferring to whichever source is in front of you, ⛔ incl. the other agent's self-blame. ⭐ Record **UNRESOLVED** and name who settles it. 🔬 31-Aug: "not in my transcript" is a RECONSTRUCTION, ⛔ not a query ⇒ ⭐ **S-5 applies to your OWN context too.** ⛔ "not established" quietly picks a side.
- 🔢📏🔝 **J-2 OPERATIONAL — STATE THE QUERY THAT PRODUCED EACH FIGURE *BEFORE* COMPARING OR COMBINING THEM.** ⛔ If both cannot be stated, ⛔ the comparison is NOT made. 🔬 31-Aug: `grep -c CRITICAL` (=3, ANY mention) vs `"level":"CRITICAL"` (=1, true severity) were compared as one ⇒ a phantom "unexplained CRITICAL". ⭐ Same shape as COST-30×2 and NIACL 2×394.31 ⇒ ⭐ **grain and metric-definition are ONE rule.**
- 🔍🕳️🔝 **S-5 — "ABSENT FROM WHERE I LOOKED" IS ⛔ NOT "ABSENT".** 🔬 31-Aug: called `cron_officer_briefing` unobservable after checking logs + markers; the artifact was a THIRD class — `cron_heartbeat` DB rows. ⇒ ⭐ Before calling anything missing/inert/unobservable, ENUMERATE THE ARTIFACT CLASSES (log · marker · DB row) and SAY WHICH WERE SEARCHED. ⛔ An incomplete search space is not a negative result.
- 🃏🔬🔝 **⛔ A CARD NEVER SUPPLIES A MEASUREMENT — ⛔ NEVER CERTIFY EVIDENCE YOU CANNOT INSPECT.** 🔬 31-Aug FILE 69 ordered `F_RECIPIENT_CONFIRMED = YES` on 3 legs, one a screenshot never shown to me ⇒ ⛔ REFUSED, recorded `NOT PROVEN in MY record`. ⭐ 3rd instance (D-F · V-3 · leg-c). ⭐ Keep **A** system-generated · **B** externally observed · **C** 👤 Rama's own typed words APART; ⛔ never silently promote A/B → C.
- 🏷️🔬🔝 **[LABEL EVERY CLAIM'S PROVENANCE — 🔬 MEASURED · 📄 EVIDENCE · 💭 INFERENCE · 👤 RAMA'S](provenance_labels_23aug.md)** — ⭐ certifying what you ⛔ could not inspect is the failure. ⛔ **A CONSTANT in a "MEASURED" column is a LITERAL — scan fixtures for zero-variance** → [24-Aug](fabricated_fixture_column_24aug.md)
- 🧬⛔🔝 **⛔ ANCESTRY ALONE CANNOT SAY *"NOT DELIVERED"* — `N9-07` names `7649cd8`, ⛔ NOT an ancestor of `4568385`, yet its patch is **BYTE-IDENTICAL** to it (8,539 B, same 2 files) = a CHERRY-PICK.** ⇒ ⛔ **ancestry says NO, substance says YES.** ⭐ Always ask whether the SUBSTANCE is on the deployed path by another mechanism.
- 🤖⛔🔝 **[⛔ NEITHER A CARD NOR A REVIEWER MAY SPEAK FOR RAMA — `WC-PATTERN #7` (a ruling he NEVER MADE) and `#8` (a reviewer AUTHORISING live money), SAME DAY, HOURS APART](UNPUSHED_PENDING_DEPLOY_LEDGER.md)** — 🔴 **F2a's MIS 3.5× is HELD; GTT is NOT.** ⛔ **A GREEN GATE IS NEVER DEPLOY AUTHORISATION.** 🧭 Tracker = `MASTER_REGISTER §FX`.

- ⏳🔴🔝 **⛔ TENSE IS LOAD-BEARING — a BUILT-BUT-UNPUSHED row carries TENSE AND PRECONDITION in one sentence** → [detail](feedback_tense_drift_09aug.md)
- 🔁🔴🔝 **⛔ A PRACTICE RECORDED BUT NOT CARRIED IS NOT ADOPTED** → [detail](feedback_carry_the_countermeasure_09aug.md)
- 📏🔴🔝 **⛔ EVERY PERCENTAGE CARRIES ITS BASE OR IT IS NOT A NUMBER** → [detail](tick1_threshold_base_mixup_09aug.md)
- 🔁🔴🔝 **⛔ AN UNSOURCED VALUE DOES NOT AGE INTO BEING SOURCED — only a QUOTED, TIMESTAMPED Rama line closes it** → [detail](feedback_unsourced_promoted_by_repetition_09aug.md)
- 🔍🚫🔝 **⛔ AN ABSENCE NEEDS A CHECK WIDE ENOUGH TO HAVE FOUND THE THING — state the SEARCH WIDTH beside the zero** → [detail](feedback_absence_needs_wide_check.md)
- 🕰️🛑🔝 **⛔ SHOWING A STALE VERDICT AS THE *CURRENT* ANSWER IS ITSELF THE UNSAFE ACT — *"I must not invent a verdict"* does ⛔ NOT license it** → [detail](stale_verdict_as_current_answer_15aug.md)
- 📊⛔🔝 **EVERY HEADLINE NUMBER CARRIES ITS POPULATION DEFINITION** — numerator · denominator · what the population IS · exclusions · how `DATA_UNAVAILABLE` is treated · the time window. ⚠️🔴 **A wrong denominator does ⛔ NOT look wrong — it looks like a RESULT.** ⭐ The population definition is the **only** thing that makes it detectable.
- ⚖️🕳️🔝 **DOCUMENT ERRORS ARE RE-DERIVABLE; STATISTICS ARE ⛔ NOT.** 🔬 16-Sep: all **7** counting failures resolved because the file, column, shape, fence or heading could be **MEASURED AGAIN**. ⚠️ **Once output becomes rates over trading data, that ground truth is GONE** ⇒ ⭐ **state the population BEFORE the first number, ⛔ not after a dispute.**
- 🧮📏🔝 **RECORD SHAPE FOR ANY COUNT: WHAT was counted · HOW · WHICH POPULATION · WHEN · WAS THE SOURCE AUTHORITATIVE.** ⛔ **Never infer a population from a STRING OCCURRENCE when a structured field, column or source-level selector exists.** 🔬 16-Sep: **771** is a CORRECT count of `tick_size=0.05` rows and is ⛔ **NOT** the RI12 fallback set — ⭐ two true statements about different sets; one answers the question.
- 🚫📉🔝 **⛔ A SAFETY METRIC READING *ZERO* PROVES NOTHING UNTIL THE SELECTOR OR PATH IS SHOWN REACHABLE.** ⭐ "Zero incidents" and "a selector that CANNOT MATCH" look identical. 🔬 16-Sep: `force_close_entry_cancelled`=**0** and EOD *"0 orders cancelled"* daily — because the sweep selects `PENDING_FILL` while a working entry sits at `PENDING`. ⭐ **Prove reachability FIRST, then read the zero.**
- 🎯🕳️🔝 **A RIGHT ANSWER REACHED BY A WRONG METHOD IS THE WORST CASE — nothing in the output invites a second look.** 🔬 16-Sep: grepping lines *containing* `0.05` returned **771**; counting the COLUMN returned the same **771** for the right reason. ⭐ **Measure the STRUCTURE, ⛔ never the string** — 7 counting failures in one day across 3 parties, all caught that way.
- 🛡️⛔🔝 **A GUARD IS A PRECONDITION, NEVER A MESSAGE AFTER THE ACTION — if a command must not run, it must not be REACHABLE.** 🔬 16-Sep 22:39: `scp … trading-vm:/tmp/q.sql && echo "(… aborted)"` printed *aborted* BECAUSE the write SUCCEEDED ⇒ a file on PRODUCTION. ⭐ 3rd inverted indicator (normalizer rc · `grep -c` rc · this echo) → SYSTEM_MAP `INCIDENT-PROD-TMP-WRITE-16SEP2026`
- 🔤💥🔝 **MEASUREMENT OUTPUT GOES TO A FILE OPENED AS EXPLICIT UTF-8; KEEP MEASUREMENT STDOUT ASCII.** 🔬 17-Sep: a cp1252 console crashed on `🔝` just AFTER a measurement finished — harmless that time. ⚠️ Mid-run, the evidence is cut off silently, and ⭐ **a truncated evidence file looks exactly like a short one.**
- 🎯🕳️🔝 **A GUARD KEYS ON THE MARKERS *THIS* RUN WROTE — ⛔ NEVER ON ANY OCCURRENCE OF A TOKEN IN THE FILE.** 🔬 17-Sep: the applier's FAIL-on-any-`@@` fired on OLD ledger text, not a leftover placeholder. ⭐ A pattern that cannot tell its target from its background proves nothing either way: ⛔ it fails UNINFORMATIVE, not safe.
- 🔍✅🔝 **EVERY ABSENCE CLAIM NEEDS A POSITIVE CONTROL — STANDING, ⛔ not a one-off recovery.** 🔬 17-Sep: the crontab-writer regex could not match the writer ALREADY KNOWN (`crontab deploy/cron/…`), so its zero meant nothing; the 2nd pass's zero counted only because it FOUND that writer. ⭐ Same rule as the top "A ZERO IS EVIDENCE" line.
- 📦⚖️🔝 **PRESERVE PRIMARY EVIDENCE THAT EXISTS NOWHERE ELSE; ⛔ DON'T DUPLICATE WHAT IS BYTE-IDENTICAL ELSEWHERE WITH ITS HASH RECORDED.** 🔬 17-Sep: the crontab scan outputs (nowhere else) were kept with hashes; prod `/tmp/q.sql` was ⛔ not copied — the transcript heredoc reproduces it, md5-verified (👤 Rama: no copy). ⭐ The distinction IS the rule.
- 🎛️🕳️🔝 **A CONTROL THAT CANNOT CHANGE THE OUTPUT VARIABLE DOES NOT TESTIFY ABOUT THAT VARIABLE.** 🔬 17-Sep: all 4 arms of the drift derivation returned `has_critical=true` (5 absent jobs sat in every arm) ⇒ the controls proved BUCKET assignment only; "the evaluator line cannot raise severity" stayed a CODE READING. ⭐ Ask of each control: which output did it FLIP?
- 🔤🚫🔝 **A ZERO FROM THE TOOL IS AN ABSENCE-INFERENCE TOO — EVERY ZERO CARRIES A POSITIVE CONTROL RUN WITH THE SAME FLAGS AND THE SAME LOCALE.** 🔬 17-Sep: a default-locale `grep -F` read **0** for an emoji-bearing literal that `LC_ALL=C grep -F` and Python both found. ⭐ Anchor matches on the ASCII part; ⛔ a control that reads 0 is not a control.
- 📑💥🔝 **AN INSERTION INTO A LINE-CITED RECORD INVALIDATES EVERY CITATION BELOW IT — APPEND; if you must insert, fix every citation in the same operation.** 🔬 17-Sep: a new rule at line 51 shifted one cited as `MEMORY_RULES 48–51`; moved to 52 unprompted. ⭐ Search for citations WITH a control first — the first search read 0 (backticks).
- 🗄️🕳️🔝 **SQLite `immutable=1` DOES NOT READ THE WAL — on a WAL-mode DB it shows the LAST CHECKPOINT, ⛔ not the data.** 🔬 17-Sep: `evaluation_runs` read **0** under `immutable=1`, **1** with the WAL recovered (byte-copies). ⭐ Copy main+WAL and read the copy; preserve under NON-pairing names — a paired copy opened normally CHECKPOINTS and DELETES its WAL.
- 🔎🪞🔝 **A PROCESS CHECK MATCHES ITS OWN COMMAND LINE — exclude your own PID, split the pattern; ⛔ `pipeline || echo NONE` never fires when the LAST stage succeeds.** 🔬 17-Sep 18:00: `ps | grep -cF` read **1** and **2**, both inflated by the remote shell itself; true 0 and 1 (control `/usr/sbin/cron`).
- ✂️📑🔝 **INSERT AT A LINE BOUNDARY ASSERTED BY CONTENT — ⛔ never at a substring match inside a row.** 🔬 17-Sep 17:51: a PATHS section landed INSIDE a table row, its tail glued to another row; caught only because the next write read the region first. ⭐ After any insert, re-read the seam.
- 🚫💾🔝 **ON A READ-ONLY PASS, ⛔ NO `>` OR `rm` INSIDE THE REMOTE COMMAND — `/dev/shm` IS STILL A WRITE.** 🔬 17-Sep ~18:00:28: a stray `ps … > /dev/shm/.none; rm -f …` created and deleted a file on the testing VM mid-sequence; recorded as a deviation. ⭐ Redirect on the PC side of the pipe.
- ⚠️🔍🔝 **[A green check is evidence ONLY if it could have been red](feedback_verify_rc_not_output.md)** — errored cmd · stale baseline · vacuous test · ⭐ a gate POISONED by the artifact the change prevents. ⛔ **Delete the artifact, THEN measure.**
- 📐⛔🔝 **[A CHECK WITH NO FAILING INPUT MANUFACTURES CONFIDENCE (`V5`)](tautological_check_class_05aug.md)** — ⭐ a MISSING check leaves you uncertain; a **TAUTOLOGICAL one leaves you WRONGLY certain.**
- 🕳️🔎🔝 **⛔ A GAP YOU *EXPECT* IS STILL A CLAIM — a negative grep proves ONE SHAPE is absent; ask if a STATE table holds ≥2 samples** → [detail](expected_gap_is_still_a_claim_15aug.md)
- ⚠️🔎🔝 **[An audit finding is a HYPOTHESIS — verify its premise](feedback_verify_the_finding_premise.md)** — ⭐ two sources disagreed and BOTH were wrong. Refusing an item with evidence is valid.
- 📅⛔🔝 **[NEVER ASSERT A CALENDAR FACT FROM RECOLLECTION — quote the line](feedback_verify_scheduling_facts_31jul.md)** — a false holiday claim nearly moved an IRREVERSIBLE step. ⛔ Cause: a yaml COMMENT read as DATA.
- 🚫🔤🔝 **[NEVER classify/count/filter by FREE TEXT when a structured status exists](feedback_never_classify_by_free_text.md)** — rendering text OK; BRANCHING on it is the defect. Sweep the CLASS, ONE classifier.
- ⚖️🔎🔝 **[LIVE vs LATENT decides stop-and-report](feedback_live_vs_latent_findings.md)** — judge by REACHABILITY. LIVE ⇒ STOP. LATENT ⇒ CONTINUE + document + pin with a test.

### Evidence discipline (cont.)
- 🏦🔬🔝 **"IS THE BOOK FLAT?" IS ANSWERED BY THE BROKER, ⛔ NEVER BY THE LOCAL `trades` TABLE.** 🔬 09-Sep pre-push: local said GRAPHITE `OPEN`; the broker said **net 0 / day 0 / holdings 0** — flat, with one ORPHAN GTT left behind. ⭐ Local status lags a manual close and an orphaned GTT looks like nothing at all locally. ⛔ Do not block or proceed on the local row.
- 🧨🔍🔝 **MEASURE A DEPLOY HOOK'S BLAST RADIUS BEFORE JUDGING DEPLOY TIMING.** 🔬 09-Sep: reading the armed hook showed `checkout -f` + a CONDITIONAL crontab install and ⛔ NO restart ⇒ a live-session push could not touch the running process, and the "wait for the close" advice was over-cautious. ⭐ Read the hook; ⛔ do not infer risk from the word "deploy".
- 🔐⏳🔝 **A PERSISTED BACKOFF STOPS A *FIXED* CREDENTIAL FROM EVER BEING TRIED — A RESTART DOES ⛔ NOT CLEAR IT.** 🔬 09-Sep prod: password rotated + watcher restarted, yet `alert_watcher_smtp_state.json` held `consecutive_auth_fails: 11` ⇒ `min(60*2^(n-1),1800)` = the **30-min cap** ⇒ SMTP ⛔ never tried; the alert went Telegram-fallback, marked `.delivered`. ⭐ Clear the counter, then prove the CHANNEL.
- 🪞🔬🔝 **PROVE A CHANNEL BY CONTRAST, ⛔ NOT BY ONE GREEN RESULT.** 🔬 09-Sep the proof was TWO sentinels 64 s apart on one code path: 12:21:30 `via TELEGRAM fallback` (backoff on) vs 12:22:34 plain `-> .delivered` (backoff off). ⭐ The **ABSENT** fallback tag is the evidence; a single `.delivered` is compatible with BOTH outcomes and therefore proves neither.
- 🔔🕳️🔝 **A `.delivered` SENTINEL DOES ⛔ NOT MEAN THE EMAIL WENT — the TELEGRAM FALLBACK renames it `.delivered` TOO** (`alert_watcher.py` → `mark_delivered`; ⛔ no retry, ⛔ no `.failed`). 🔬 09-Sep prod showed **59 `.delivered` · 0 `.failed` · 0 pending** while SMTP had been dead **2 days**. ⭐ Channel truth is the LOG: `via TELEGRAM fallback`. ⛔ Never read the EXTENSION as proof a channel worked.
- 📡🔬🔝 **A CHECK THAT NAMES A REMOTE CAUSE MAY NEVER HAVE CONTACTED IT.** 🔬 09-Sep `preflight.VmIpUnchangedCheck` says *"update the Kite dev-console IP-allowlist"* but ⛔ only diffs `ifconfig.me` against a LOCAL file — it ⛔ never calls Kite. Its sandbox baseline held **production's** IP (clone artifact). ⇒ ⭐ Read a check's SOURCE before repeating its remedy.
- ⏱️🕳️🔝 **A ONCE-A-DAY CHECK DATES THE *DETECTION*, ⛔ NEVER THE ONSET — take the date from the CONTINUOUS observer.** 🔬 09-Sep the 08:20 canary said prod email broke **08-Sep**; the alert-watcher loop showed last-good **07-Sep 09:20:11** and first-fail **07-Sep 15:03:15** ⇒ ⭐ a **whole day** earlier, which flipped the verdict from *"caused by yesterday's credential work"* to **INDEPENDENT DEFECT**.
- 🔬⚖️ **A SHARPENING WITHOUT ITS OWN FALSIFIER CANNOT GO RED.** ⭐ Strengthening a claim past its source? State the measurement that would REFUTE it, in the same output. 🔬 28-Aug: two of mine died to one query. ⛔ Applies to MY output too.
- 🧮🔎 **COMPARE IN ONE CALL, ⛔ never across two.** ⭐ Two timestamps from separate calls cannot establish skew; one call returning both epochs can. 🔬 28-Aug: an apparent 15-min PC/VM skew was an artefact — real skew **1 s**.
- 🧪🧮 **FINGERPRINT A BASELINE FAILURE SET, ⛔ never hand-type it.** `sort | sha256sum` the IDs, then `comm -13` (NEW=EMPTY) **and** `comm -23` (MASKED=EMPTY). ⚠️ The 2nd matters as much. 📄 `docs/RELEASE_CRITERION.md`
- 🚦📈 **RC IS AN INPUT, ⛔ NEVER THE VERDICT.** ⚠️ `RC=1` is expected while the standing set is non-empty — ⛔ but it also occurs on a NEW failure. ⭐ Say **DIFFERENTIALLY CLEAN**; ⛔ never *"the gate passed"*.

- 📉🧪🔝 **S-2 — ⛔ NO DIFFERENTIAL CLAIM FROM A PARTIAL STREAM. ⭐ A GATE IS ONLY ITS COMPLETED RESULT.** 🔬 30-Aug: a 38%-complete progress stream was compared position-by-position and reported **2** new failures; the finished gate showed **9**. ⇒ ⛔ Interim observations are HYPOTHESES — ⛔ never reported as findings, ⛔ never used as a gate.

### Method
- 🚩⏱️🔝 **LET THE EVENT'S OWN MARKERS SAY WHAT HAPPENED — ⛔ NEVER A DEADLINE.** 🔬 16-Sep: a doc carried **TWO** checkpoints for one check ⇒ a 3-min-slow exit read **STOP** under one, **proceed** under the other. ✅ Fix: **ONE** checkpoint + read `start`/`done` markers — start+done⇒proceed · start, no done⇒**in progress, wait** · **no start⇒the finding.** ⚠️ Read them in a sink that CAN carry them.
- ⏰⚖️🔝 **THE CLOCK DECIDES *WHEN TO LOOK*, ⛔ NEVER *WHAT A STATE MEANS*.** 🔬 16-Sep: a summary cut a gated check to *"at 17:30, adjudicate"*; a cold reader then reads **ACTIVE** (⛔ not exited yet) and **FALSE-STOPS a healthy deploy for being 5 min early.** ⭐ State the **PRECONDITION**, ⛔ not the hour — at every place the sequence is **SUMMARISED**, ⛔ not only where specified.
- 🔢🕳️🔝 **⛔ A SUBSTRING COUNT OVER A DOC THAT DISCUSSES ITSELF IS NOT A CHECK — VERIFY STRUCTURALLY.** 🔬 16-Sep, **3× in one day across TWO reviewers**: recording a count **changed** it (29→30); a heading pattern that missed the real format returned *"4 present, 22 missing"*. ⭐ Assert an **INVARIANT**, ⛔ never a total. ⚠️ **A number always looks like evidence.**
- 🏷️🕳️🔝 **A DOC THAT NAMES A VERSION IS STALE THE MOMENT IT IS USED TO PRODUCE THE NEXT ONE.** 🔬 16-Sep, **3× in one day**: a card named the current artifact → applying it created a new one → the card now named the **superseded** file, which was KEPT on disk and verified **CLEAN**. ⭐ Reference by **ROLE**; keep identity in **ONE** place. ⛔ An identity check cannot see a newer artifact it does not name.
- 📋🕳️🔝 **⛔ NEVER LET TWO DOCS CARRY THE SAME PROCEDURE — one gets updated, the other doesn't, and BOTH read as authoritative.** 🔬 16-Sep: a prediction's own identity-check step still named the SUPERSEDED artifacts, and every superseded file was KEPT on disk ⇒ verifying them MATCHED ⇒ ⭐ the gate **CERTIFIED the wrong set and reported GREEN**. ⭐ Data ≠ procedure; reference by NAME, ⛔ never by version.
- 🔭🕳️🔝 **OBSERVABILITY = SOURCE + LOGGER + LEVEL + SINK ROUTING — ⛔ NOT "the event exists in the code".** 🔬 16-Sep, TWO near-misses from that one gap: 3 INFO rows hunted in a WARNING+ journal ⇒ would have read *"manager did not come up"* and STOPPED a correct deploy; and must-ABSENT rows checked in a sink that cannot carry them ⇒ green BY CONSTRUCTION. ⭐ Split sinks by ORIGIN, ⛔ never by level.
- 🔁🕳️🔝 **AN IDEMPOTENT STEP DOES ⛔ NOT MAKE THE SEQUENCE RE-RUNNABLE — a PRECEDING gate that asserts a PRE-STATE re-arms the same trap one step earlier.** 🔬 16-Sep: guarded writes gained 3 outcomes (`ALREADY_DONE`/write/`REFUSED_DRIFT`), ⛔ but Gate 3's absence+pre-md5 checks are ALREADY falsified by a partial run ⇒ the re-run STOPS before reaching them. ⭐ Audit EVERY precondition UPSTREAM, ⛔ not the step you fixed.
- 🧵🕳️🔝 **⛔ WRITE RECORDED WINDOWS PATHS WITH FORWARD SLASHES — `D:/Projects/trading-system`.** ⚠️ A write layer eats `\t`/`\n`/`\r`/`\U`: 🔬 03-Sep **8** paths became `D:\Projects<TAB>rading-system`, ⛔ a path that does not exist, in 5 files incl.
