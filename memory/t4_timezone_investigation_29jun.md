**T4 Phase-0 INVESTIGATION ONLY (29-Jun) — no fix implemented; design pending (Web Claude owns).** Confirmed root cause of tonight's wrong "13:47 IST / market open" reading (real time was 19:22 IST, post-close).

**ROOT CAUSE (single layer = MSYS2/Git Bash `date`):** Git Bash (the agent's Bash tool — it is MSYS2, NOT WSL; WSL has no installed distros) ships **NO IANA zoneinfo database** — `/usr/share/zoneinfo` does not exist. So `TZ='Asia/Kolkata' date` can't resolve the zone name and **silently falls back to UTC** (printed `14:34 +0000 GMT`). That is exactly the command the agent used tonight to check time → read UTC as if it were IST. Caught via `date -u` (UTC, Git Bash gets this right) + an SSH cross-check to the VM clock. POSIX-form `TZ='IST-5:30' date` → correct +0530 (no zoneinfo file needed); bare `date` → correct +0530 (inherits the Windows system TZ).

**LEADING HYPOTHESIS REFUTED:** it was NOT missing/broken Python `tzdata`. Both PC interpreters — venv (Python **3.14.3**) and system (`/c/python311`, **3.11.9**) — have **tzdata 2026.2** and `ZoneInfo("Asia/Kolkata")` returns **+0530 IST** correctly (TZPATH empty ⇒ using the pip tzdata pkg). (Consistent with [[pc_test_env_hygiene]]: tzdata was pip-installed 22-Jun.)

**APP IS IMMUNE (code audit):** the single time helper `core/time_authority.now_ist()` = `datetime.now(tz=timezone(timedelta(hours=5,30), name="IST"))` — a **fixed UTC+5:30 offset, explicitly zoneinfo-free** ("no dependency on zoneinfo for portability"). India has no DST ⇒ fixed offset is always correct, on ANY machine, given only a correct OS **UTC** clock. Repo-wide audit (operational dirs, excl tests/venv/sats): **zero** zoneinfo/pytz/tzlocal usage, **zero** subprocess/shell-out to `date`, **zero** naive `datetime.now()/utcnow()/today()` — every module routes through `now_ist()`. The FIX-189 market-window guard (`main.py:417`), all `core/market_windows` calcs (`is_market_open`/`is_within_market_hours`/`is_market_day`, default `now=now_ist()`), and the EOD threads all use `now_ist()`.

**BLAST RADIUS = PC operator-tooling only.** Nothing operational consumed the broken layer: the ONLY thing that read Git-Bash `TZ=Asia/Kolkata date` tonight was the agent's deploy-timing probe (corrected before deploy via UTC + VM cross-check; the Telegram deploy still went out correctly post-close). No app code, no trade, no VM decision touched it. **VM is fully healthy / NOT at risk:** clock 20:06 +0530, NTP `active` + `synchronized: yes`, TZ Asia/Kolkata, `/usr/share/zoneinfo/Asia/Kolkata` present, app `now_ist()` → +0530. All trading/market-window/squareoff decisions run on the VM. Existing time-integrity infra: `time_authority.record_broker_skew` + `broker/clock_skew_probe` (broker-vs-local skew, critical→`kill_switch.soft_kill`); real anchor = NTP/systemd-timesyncd.

**LEAN FIX — BUILT + DEPLOYED 29-Jun (operator-tooling ONLY; NO trading-code/parity change; NO restart — the service imports none of these; main = single source).** 3 standalone scripts:
- `scripts/ist_now.sh` — **the approved IST command.** Prints `now_ist().isoformat()` (resolves repo root + project venv; runs from any CWD). NEVER `date` with a zone name. Immune to the MSYS2 bug.
- `scripts/check_tz.sh` — loud self-check: compares `now_ist()` offset (+0530) vs the **suspect** `TZ='Asia/Kolkata' date` offset; mismatch ⇒ FAIL LOUD + exit 1. On THIS MSYS2 PC it correctly FAILS (`15:04 +0000` vs `20:34 +0530`) — that failure IS the proof. Test hook `CHECK_TZ_FAKE_OFF`/`_HM`. Diagnostic/deterrent only.
- `scripts/deploy_preflight.py` — run BEFORE any market-window-gated action. Anchors ONLY on `date -u` (UTC, no zoneinfo needed) + the VM. Steps: (1) run check_tz.sh for VISIBILITY, never hard-block (this PC always fails it); (2) `|PC date -u − VM ssh date -u| ≤ 120s` else FAIL LOUD (the ONLY use of PC time — agreement, not the decision clock); (3) market-state AUTHORITATIVE from the VM = holiday-aware `MarketWindows.is_market_open(now_ist())` built from `load_all()` config; market-gated + OPEN ⇒ FAIL LOUD (no mid-session deploy). Pure `evaluate()` is unit-tested. CLI: `--vm-host`(def `trading-vm`)/`--tolerance`/`--not-market-gated`.

**OPERATING RULE (in SYSTEM_MAP + PATHS):** ❌ NEVER `TZ='Asia/Kolkata' date` in Git Bash. ✅ Use `scripts/ist_now.sh` / `now_ist()` / `date -u` (UTC) / `TZ='IST-5:30' date` (POSIX form works — no zoneinfo file needed). Before deploy/restart: `python scripts/deploy_preflight.py`.
