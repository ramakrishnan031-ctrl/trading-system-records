**⚠️ Runbook (+ [[build_plans_commitA_B_d1_07jul]] "@3787") MISFRAMED A-3** as a flatten/squareoff last-mile re-check. **The actual A-3 finding is an ENTRY-path kill-switch TOCTOU** inside `orders/order_placer.py::place()`:
- OP-LM1 `is_active("entry")` check at **:944** runs BEFORE the pre-submit network I/O — `_fetch_ltp` (:1002/:1096), get_quote drift, `_check_liquidity` (:1188) — and the real submit `self._engine.execute()` is at **:1215**. A SOFT_KILL activated by another thread in that window is not re-checked → **one entry leaks past a just-activated kill** (`soft_kill` has NO order-cancel backstop; only `hard_kill` cancels via `on_hard_kill_cancel_fn`). Bounded: leaked entry is still SL/TGT-protected (LIMIT_TRIPLE), and HARD_KILL escalation's flatten sweep catches it.

**The flatten/emergency-exit "last mile" (what the runbook described) is ALREADY covered by Wave-1/2 (FIX-190 Bug A):** both `kill_switch.py:1102` (HARD_KILL sweep) and `order_placer.py:3744` (emergency exit) call `determine_close_direction(adapter,...)` → `broker_net_qty()` = **fresh broker position at execution** (paper signed via [[h12_paper_positions_signed_06jul]]), skip-if-flat (no double-flatten), mark EXITING. NO gap there.

**Root cause:** OP-LM1 was "last-mile" for the OLD flow; later additions (FIX-073 EOD cutoff, FIX-180 slippage LTP, drift re-quote, FIX-134 liquidity) inserted network I/O between the check and the submit, so the single check drifted away from the true last mile. No re-check was ever added at `execute()`.

**Design (recommend):** ADD a cheap in-memory `is_active("entry")` re-check at the TOP of the 429-retry loop (:1213), immediately before each `_engine.execute()`, AFTER all network I/O — reuse OP-LM1's exact failure path (`_handle_placement_failure` → FAILED + release + raise `OrderRejectedError`). KEEP OP-LM1 @944 as an early-out. Trade is PENDING at that point → PENDING→FAILED is legal, terminal-guard does NOT fire; close_trade CAS uninvolved (entry reject, not exit). Purely additive reject gate: cannot weaken/race/double-flatten; shrinks the window from seconds (I/O) to microseconds. Guard with `_kill_switch is not None`. **Validation:** RED→GREEN test where an I/O callback (`_fetch_ltp`/`_check_liquidity`) flips kill→SOFT_KILL mid-place → assert execute NOT called + trade FAILED + reservation released; happy-path unaffected; Wave-1/2 emergency-exit + HARD_KILL suites stay green; both modes. **Rollback:** tiny blast radius (a few lines, entry path only, no schema/config/exit-path) → clean `git revert`; cannot reintroduce a naked position. **Parity:** mode-agnostic single path; H-12 signed positions matter only to the (already-correct) flatten path, not the entry re-check. STOP — no build.
