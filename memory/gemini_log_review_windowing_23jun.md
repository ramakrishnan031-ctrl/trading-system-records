**gemini_log_review (16:20 EOD) windowing weakness — ✅ IMPLEMENTED + DEPLOYED 23-Jun (commit `8c80a15`; cron tooling, picked up on the next scheduled run, no restart needed).** Shipped: `_process_start_ts` + restart-aware `_extract_warning_plus` (skip ts < last startup marker, whole-file fallback) + `_emit_review_failure_alert` (full-failure CRITICAL sentinel + Telegram WARN + "REVIEW FAILED" stub, low-noise). Tests: `tests/unit/test_gemini_log_review_hardening.py` (6 green). Design rationale below.

**3a — the tgt_retry alert was STALE (confirms the prior session's #2):** the P2 tgt_retry 3-arg `is_within_market_hours` fix (commit `8812026`, in `6bed838`) is LIVE since the **12:28 restart**; today's 230 TypeErrors were ALL pre-restart (08:15→12:28:14), ZERO after. Yet `reports/log_review/eod_review_2026-06-23.md` opens with "Operational Audit: Target Retry Manager Cycle Error" reporting it as a current crash → gemini reviewed already-fixed pre-restart lines.

**3b — root weakness:** `scripts/gemini_log_review.py:_extract_warning_plus` reads the **OLDEST 500** WARNING/ERROR/CRITICAL lines from the daily `system_<date>.log` (iterates from the top, stops at 500) with **NO restart cutoff**. Two failure modes: **(A)** stale pre-restart errors surface as "current" (today); **(B) worse** — a heavy-error morning consumes the 500 cap so the **post-restart afternoon (the window that matters) is never reviewed** → real afternoon issues missed.
Design options (NO code this phase):
- **(1) RESTART-AWARE [recommended]** — review only lines with ts ≥ the running process's start; kills A+B by construction. Restart-timestamp source: systemd `ExecMainStartTimestamp` (reliable — gave 2026-06-23 12:28:18 IST via `systemctl show trading-system -p ExecMainStartTimestamp`) OR the app's own startup log marker (keeps the script self-contained, no shell-out) OR a session-id row; use the LATEST start; fall back to whole-file if none found.
- **(2) RECENCY** — most-recent N lines (tail, not head); simple, no restart dependency, but can still mix pre/post-restart.
- **(3) TIME-WINDOW** — last N hours; simplest but arbitrary.

**FINALIZED (23-Jun 21:00) — CHOSEN = restart-aware via the app's startup log-marker (self-contained, no systemd):** cutoff = the ts of the **LAST** app-start line in the same daily log — `logger="main"`, msg `"Trading System v<ver> starting (mode=<mode>)"` (`main.py:1388`; logged once per process start — today 08:15:04 COLD + **12:28:19 WARM**). Preferred over systemd `ExecMainStartTimestamp` because the script already reads this log (no systemctl shell-out, no unit-name coupling, robust to start method). **Exact `_extract_warning_plus` change:** (1) new helper `_process_start_ts(log_path)` scans the file, returns the `"ts":"…"` of the LAST startup-marker line (regex on raw line) or None; (2) in the W/E/C loop, pull each line's ts via `re '"ts":"([^"]+)"'` and **skip if `ts < start_ts`** — lexicographic string compare is valid (all ts share the +05:30 offset + zero-padding, so lexical == chronological; no datetime parse needed); a line with no parseable ts → include (conservative); (3) apply the 500 cap AFTER the cutoff so the cap now covers the **post-restart window** (kills both A and B). **Fallback:** start_ts None (no marker / rotated log) → whole-file oldest-500 (today's behaviour). Latest marker wins on multi-restart days. Pin the marker string in a test (assumes a single tz offset — revisit if logs ever mix offsets).

**3c — cascade degradation (separate reliability item):** today's Gemini cascade (Flash Low/Med/High) hit quota/timeout (`cron-gemini-review.log`) before a later model produced the report (degraded-but-completed; it heartbeated). **A FULLY-failed review is a blind spot:** on all-models-None, `run_review` returns 1, writes NO report, NO Telegram, NO sentinel, and does NOT heartbeat — only `log.error("all models unavailable")`. So a dead review surfaces to Rama ONLY indirectly (missing heartbeat / absent `eod_review_<date>.md`), never an active alert. **FINALIZED failure-sentinel (23-Jun 21:00):** trigger = `run_review`'s `if review_text is None` branch (all cascade models exhausted) — the ONLY new alert point, so a **degraded-but-completed** review (non-None, like today) stays QUIET (low-noise). Before `return 1`, call `alerts.critical.write_critical_sentinel(title="[LFL836] gemini_log_review FAILED — no AI EOD review for <date>", body=<all-models-exhausted; investigate agy quota/connectivity; trading unaffected>, source_module="gemini_log_review", sentinel_dir=ROOT/"data_store", context={"severity":"CRITICAL"})` → the systemd alert-watcher **emails** it (reliable, Telegram-independent fallback — same path cron_watchdog uses), + optional best-effort Telegram WARN. Optional nicety: write a `eod_review_<date>.md` "REVIEW FAILED" stub so the absent-report signal is explicit. Heartbeat stays success-path-only (failure → no heartbeat = secondary indirect signal; the sentinel is the primary loud one). See [[cron-heartbeat-falsealarms-23jun]].
