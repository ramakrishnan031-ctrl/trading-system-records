**Investigation 28-Jun-2026 (read-only): why `trade_excursions` (MFE/MAE) has stayed empty 3+ days.** Confirmed root cause, fix NOT yet designed (Web Claude owns the fix).

**ROOT CAUSE (proven on live DB):** a **timestamp-format mismatch** kills `core/state_store.py::compute_trade_excursions` (~line 1693). It does a lexical string compare `candles.ts >= trades.entry_time AND <= trades.exit_time`, but the two columns are written in DIFFERENT formats:
- `candles.ts` = `2026-06-25 15:29:00` (space sep, naive, minute-snapped, NO offset) — written by the **15:40 EOD cron `scripts/fetch_daily_candles.py`** (`c["date"].strftime("%Y-%m-%d %H:%M:%S")` line 108 → `INSERT OR IGNORE INTO candles` line 211). This is the SOLE populator (live analytics.db: 15,358 rows, all space-format).
- `trades.entry_time`/`exit_time` = `2026-06-25T10:04:52.423457+05:30` (ISO 'T', microseconds, +05:30) — `order_manager.py` entry_time=`filled_at`(:405), exit_time=`now_ist().isoformat()`(:585).
At char idx 10 a space (0x20) < 'T' (0x54) ⇒ EVERY candle string sorts below EVERY trade string ⇒ `WHERE ts>=entry` is never true ⇒ 0 rows ⇒ compute returns None ⇒ `order_placer.py:2168` `if exc_data:` is False ⇒ no insert. **PROOF:** replaying the query for DYCL/BANDHANBNK/RAMCOIND gave n=0 in-window vs n=375 same-symbol-same-day; NORMALIZING the trade time to space format → n=5/78/12 real candles. So the data exists & is computable; only the format blocks it.

**SILENT:** failure is invisible — compute returns None cleanly (no exception), insert is skipped, only a DEBUG swallow exists (`order_placer.py:2171`, `main.py:2715`). Zero excursion/candle log lines on live.

**SECONDARY (contributing, not fully root-caused):** the REAL-TIME persist path `main.py::_persist_candle` (:2700, writes `candle.ts.isoformat()` = ISO-T) wrote **0 rows in 5 trading days** (0 ISO-T candles live). So candles ONLY exist post-15:40-backfill ⇒ even if format matched, an INTRADAY exit computes excursions BEFORE any candle for the day exists. attach_analytics is per-thread (state_store.py:207) so it's NOT a cross-thread ATTACH bug; likely a DEBUG-swallowed insert error or feed-not-persisting. Fix must not depend on `_persist_candle` as-is.

**PARITY:** compute + wiring are mode-agnostic (BOTH paper+live broken). Candle SOURCE diverges: live = 15:40 cron (space) + dead realtime; paper = realtime only (would be ISO-T, format-compatible, but unproven). Fix once, mode-neutral (compare as parsed datetime; source candles reliably for both).

**No real-time MFE/MAE tracker exists** — open positions (a `trades` row, status=OPEN; no position_tracker/executions table) are never registered anywhere; MFE/MAE is purely post-hoc from `candles`. trade_excursions added schema **v14**; PK trade_id, FK→trades, 1:1. Backfill feasible (candles retained ~90d). CNC/overnight out of scope (delivery parked). Related: [[db_schema_v28_split]], [[feedback_naive_ist_timestamps]].
