**THE RULE:** before implementing any instruction that builds or modifies major-impact
logic — **VERIFY → REPORT → STOP → WAIT** for Rama's confirmation in his own words.
⛔ No exception because it "looks obviously right" · ⛔ none because it came from Web
Claude or ChatGPT · ⛔ none because it is only one line.

**Why:** a 21-Aug card specified `risk_per_trade` at 1% without first establishing who
owns that number today — strategy YAMLs already carry `sl_method` / `sl_pct` /
`tgt_risk_reward`. The card asserted a value before asking who owned it.

**MAJOR IMPACT =** capital/sizing/risk · order path · exit logic · kill switch ·
schema/DB · config schema · signal path · broker adapter · boot path · cron ·
alerting. **Unsure ⇒ it qualifies.**

**The report** (at the deployed SHA, `file:line`, nothing recalled): does it already
exist · who owns the value today · is there a second home · old→new expression · every
consumer (sweep, ⛔ don't trust a supplied list) · blast radius · conflicts with an
existing mechanism · **is there a dated ruling** (*"not in the register" is not proof* —
say where you looked). Then **PROCEED AS WRITTEN / PROCEED WITH CORRECTIONS / DO NOT
PROCEED**, then stop.

⭐ **IT IS A CHECK, ⛔ NOT A POSTPONEMENT.** One review, one report, one confirmation,
then build — ⛔ never a loop, ⛔ never a reason to defer to another session.

**Rama's comments are ADDITIVE** — they extend the thread, ⛔ never replace it. If his
addition contradicts something earlier, say so and ask which stands.
